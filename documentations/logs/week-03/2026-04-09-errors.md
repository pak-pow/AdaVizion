# DEV LOG: WEEK 3 - DAY 2

## Core Objective

Implement a domain-aware centralized error handling system and enhance quiz data integrity by tracking individual question results.

## 1. Centralized Error Handling Refactor

The error handling logic was overhauled to move away from ambiguous string comparisons toward a structured, type-safe contract.

   * **Unified Error Map:** Combined fragmented error records into a single `ERRORS` array using the `ErrorDetails` structure. This allows the API to return a consistent JSON object containing `type`, `code`, and `message`.

   * **Zod Integration:** Updated `handleControllerError` to natively process ZodError instances. This allows for the removal of manual `.safeParse` checks in controllers in favor of letting the global handler extract and format validation messages.

   * **Enhanced Prisma Handling:** Refined `P2002` (Unique Constraint) logic using a `switch` block based on the error `type`. This provides context-specific messages like "Landmark already visited" or "Quiz already answered".

   * **Middleware Alignment:** Updated `authenticateToken` and auth routes to use the new handler, ensuring security-related failures (like expired tokens) match the global error format.

## 2. Quiz Integrity & Data Transformation

   * **Question-Level Tracking:** Added the `is_correct` attribute to the `QuestionResponse` model. The quiz evaluation logic now saves the correctness of every individual answer, enabling more detailed feedback in the student's review history.

   * **Service Layer Migration:** Migrated complex data transformation logic from controllers to services. This ensures controllers remain thin and solely responsible for request/response coordination.

## 3. Security & Validation Fixes

   * **Auth Status Correction:** Updated the status code for invalid tokens from `403` to `401` to better align with HTTP standards for authentication failures.

   * **Typo Correction:** Fixed a typo in the Zod validation error messages to ensure professional UI feedback.
